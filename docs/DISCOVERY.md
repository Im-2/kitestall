## SERV Reasoning — VERIFIED from docs (no live call yet: needs OPENSERV_API_KEY)
Sources: https://docs.openserv.ai/llms.txt, /serv-reasoning/api/index.md, /api/chat-completions.md, /models.md, /tools.md, /tutorials/{prompt-guard,multipath,shadow-agent,kronos,structured-outputs,usage-and-billing}.md
- Base: `https://inference-api.openserv.ai/v1/chat/completions`, `Authorization: Bearer <key>`. OpenAI format. System message required (400 otherwise).
- Models are plain base IDs, e.g. `gpt-5.4-mini` ($1.00/$6.00 per M in/out), `gpt-5.4-nano`, `gpt-6-luna`, `claude-haiku-4.5`.
- **DIFFERENCE vs spec:** Prompt Guard and Shadow Agent are NOT model-name suffixes. They are marker tools in the `tools` array: `{type:"function",function:{name:"serv_prompt_guard"}}` and `serv_shadow_agent` (config via schema `default`s: `hint`, `max_iterations` 1–10, default 3). Shadow Agent is non-streaming only.
- Multipath and Kronos ARE model suffixes: `gpt-5.4-mini-serv-multipath`, `-serv-kronos`, `-serv-kronos-multipath`.
- Prompt Guard: on injection, SERV returns an "endpoint-shaped refusal" without calling the upstream model. Exact refusal shape: PENDING (smoke-serv.mjs records it). If the guard judge fails after arming, the request continues without verdict (so the code must treat "no verdict" as unknown, not clean). 502 if it cannot arm.
- Structured output: `response_format: {type:"json_schema", json_schema:{name, strict:true, schema}}`. Numeric range keywords rejection: PENDING (smoke test `d_numeric_range`). We avoid them regardless.
- Usage: response has `id` and `usage` (prompt/completion/total tokens). Billing per request includes guard/shadow/multipath components; per-request dollar cost is in the console Usage view; whether it is in the API response: PENDING.
- Edition-02 data-collection requirement (console.openserv.ai/settings/organization): NOT verified; human must check.

## Real settlement findings (2026-11-14)
- Funding: the faucet's reCAPTCHA was completed by the human for the demo shopper (0.5 KITE). PYUSD `claim()` is repeatable (10 PYUSD per call, ~0.001 KITE gas): `scripts/claim-token.mjs`. The shop payTo wallets hold only what they are paid.
- **Pieverse `/v2/verify` works** for PYUSD EIP-3009 payloads (`isValid:true` once funded). **Pieverse `/v2/settle` returned `{"success":false,"errorReason":"transaction_failed","transaction":""}`** for every PYUSD authorization I tried (validAfter 0 or now-60; 0.01, 1 and 24 PYUSD) on 2026-11-14. Only `scheme:"exact"` with `eip155:` networks is accepted by `/v2`. I could not determine the cause (token verified: PYUSD has `transferWithAuthorization(v,r,s)`, domain `PYUSD/1/2368` matches).
- **Decision:** `FallbackFacilitator` = Pieverse first; if it reports a failed tx with no hash, the server settles by calling the token's `transferWithAuthorization` itself (**self-relay**, relayer pays gas, nonce checked with `authorizationState`). Receipts record `payment.settled_via` (`pieverse` or `self-relay`) and every doc/UI says so. Facilitator verification is still used.
- Test USD (`0x0fF5…`, the spec's token) is not publicly mintable (`mint` reverts for arbitrary callers), so PYUSD is the demo asset.
- `kpass`/Passport: not set up (needs the human's email). All payments use the labeled dev signer; Story A's session cap is **simulated** by the dev signer and labeled as such.
- Prompt Guard is nondeterministic: the same benign sentence was sometimes blocked and sometimes passed (false positives ~10–15% in `docs/BENCHMARKS.md`). A guard block never advances the negotiation round and never retries without the guard.

## Prompt Guard false positives (2026-11-14)
- Analysis of real rounds in the dev DB (`node scripts/guard-analysis.mjs`, no SERV calls): 3 of 20 guarded rounds with a buyer message were blocked (15%). Blocked: "who are you" (1/1), "My hard spending limit is $21.25/$22.50 per unit. Can you work within that?" (1/4 each). The same sentences passed on other tries, so blocks are **non-deterministic** and not tied to one word.
- Fixed-set experiment (`scripts/guard-fp.ts`, 16 benign messages, live SERV, single call each; est. $0.14, real inference ~$0.04): current prompt **0/16** blocked; a "lean" prompt (no secrecy wording) 1/16; "lean + note" 1/16. No variant helped, so the production prompt is unchanged. The earlier 22% (9/41) is a per-message figure counting a message as blocked if ANY of up to 3 replays was blocked, so it overstates the per-call rate.
- Handling: the guard is never weakened or bypassed and a block is never retried; the Arena now shows a friendly "flagged, try rephrasing" notice (no error), keeps the typed text, and the round is not consumed.
